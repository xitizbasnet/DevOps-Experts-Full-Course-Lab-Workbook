# 🐳 Docker Installation

The following commands install Docker on an Ubuntu EC2 instance.

## Step 1 — Update Package Information

```bash
sudo apt update
```

## Step 2 — Install Docker

```bash
sudo apt install -y docker.io
```

## Step 3 — Start and Enable Docker

```bash
sudo systemctl start docker
sudo systemctl enable docker
```

This starts Docker immediately and configures Docker to start automatically when the system boots.

## Step 4 — Add the Current User to the Docker Group

```bash
sudo usermod -aG docker $USER
```

Apply the group membership without logging out:

```bash
newgrp docker
```

> 💡 **Tip:** Adding your user to the `docker` group allows you to run Docker commands without using `sudo` for every command.

# 🧩 Understanding the Docker Image and Container Model

Docker uses **images** as templates from which containers are created.

A simplified model is:

```text
Docker Image
     │
     ▼
docker run
     │
     ▼
Docker Container
     │
     ├── Running Application
     ├── Filesystem
     ├── Network
     └── Process
```

For example:

```bash
docker run nginx
```

Docker uses the `nginx` image to create and start a new Nginx container.

> 📘 **Key concept:** An **image** is a packaged template, while a **container** is a running or stopped instance created from an image.

# 🔄 Container Lifecycle

## Run an Nginx Container

```bash
docker run -d --name web -p 8080:80 nginx
```

This command:

* `docker run` — Creates and starts a container.
* `-d` — Runs the container in detached/background mode.
* `--name web` — Assigns the container the name `web`.
* `-p 8080:80` — Maps host port `8080` to container port `80`.
* `nginx` — Uses the Nginx image.

The port mapping can be visualized as:

```text
EC2 Host
Port 8080
    │
    ▼
Docker Container
Port 80
    │
    ▼
Nginx
```

## List Running Containers

```bash
docker ps
```

Displays currently running containers.

---

## List All Containers

```bash
docker ps -a
```

Displays both running and stopped containers.

---

## Stop a Container

```bash
docker stop web
```

Stops the container named `web`.

---

## Start a Container

```bash
docker start web
```

Starts the stopped `web` container.

---

## Restart a Container

```bash
docker restart web
```

Restarts the `web` container.

---

## Remove a Container

```bash
docker rm web
```

Removes the `web` container.

> ⚠️ **Note:** A container must generally be stopped before it can be removed. If necessary, stop it first with `docker stop web`.

---

## View Container Logs

```bash
docker logs web
```

Displays logs generated by the `web` container.

---

## Follow Container Logs

```bash
docker logs -f web
```

Continuously follows the container's log output.

Press:

```text
Ctrl+C
```

to stop following the logs.

---

## Enter a Running Container

```bash
docker exec -it web bash
```

Opens an interactive Bash shell inside the `web` container.

---

## Inspect Container Metadata

```bash
docker inspect web
```

Displays detailed metadata about the container, including configuration, networking, mounts, and other information.

## T2.3 — Stop All Running Containers

> ⚠️ **Caution:** This command stops **every running container on the host**. Use it carefully, particularly on shared or production systems.

## T3.1 — Run a MySQL Container

Run a MySQL container with the specified environment variable:

```bash
docker run -d \
  --name mysql \
  -e MYSQL_ROOT_PASSWORD=root123 \
  mysql
```

Verify the container:

```bash
docker ps
```

Then connect to MySQL from inside the container using the MySQL client.

> ⚠️ **Security Note:** `root123` is intentionally provided as the lab password. Do **not** use this password in a production environment. Production credentials should be strong, securely managed, and preferably stored using a secrets-management solution.

---

## T3.2 — Run Redis and Redis CLI in the Same Network

Create a Docker network:

```bash
docker network create redis-net
```

Run Redis:

```bash
docker run -d \
  --name redis \
  --network redis-net \
  redis
```

Run a Redis CLI container on the same network:

```bash
docker run -it \
  --rm \
  --network redis-net \
  redis \
  redis-cli -h redis
```

Inside the Redis CLI, test a `SET` operation:

```text
SET devops "Hello DevOps"
```

Then retrieve the value:

```text
GET devops
```

Expected result:

```text
Hello DevOps
```

This exercise demonstrates container-to-container communication using a shared Docker network.

## T3.3 — Create a Container Health-Check Script

Write a Bash script that performs the following operations:

1. Runs **5 containers**.
2. Checks their health/status.
3. Reports each container as **UP/DOWN**.
4. Cleans up the containers after the test.

A conceptual workflow is:

```text
Start

  │
  ▼
Check Container Status
  │
  ▼

  │
  ▼
```

Your script should produce a clear status report, for example:

```text

Container 2: UP
Container 3: DOWN
Container 4: UP
```

> 💡 **DevOps Practice:** This exercise introduces the basic pattern of automated health verification and cleanup that can later be incorporated into CI/CD pipelines and operational scripts.

# 💡 Best-Practice Tips

Keep the following Docker practices in mind:

* Use meaningful container names.
* Use explicit port mappings when exposing services.
* Check container status with `docker ps`.
* Review logs with `docker logs` when troubleshooting.
* Use `docker inspect` to investigate configuration and networking.
* Avoid exposing unnecessary ports.
* Use Docker networks for container-to-container communication.
* Never hard-code production credentials in Docker commands or source code.
* Clean up unused containers, images, networks, and volumes.
* Use health checks for applications that require availability monitoring.
* Avoid commands that affect every container unless you are certain of their impact.

# 🔐 AWS EC2 Considerations

When running Docker on AWS EC2, remember that **Docker networking and AWS networking are separate layers**.

For an externally accessible container, traffic generally needs to pass through:

```text
Internet
   │
   ▼
EC2 Public IP / DNS
   │
   ▼
AWS Security Group
   │
   ▼
EC2 Host Port
   │
   ▼
Docker Port Mapping
   │
   ▼
Container
   │
   ▼
Application
```

For example:

```text
Browser
   │
   ▼
EC2:8080
   │
   ▼
Docker:8080 → 80
   │
   ▼
Nginx
```

Ensure the required AWS Security Group rule exists before testing from outside the EC2 instance.
